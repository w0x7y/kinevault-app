# Exercise v1 implementation plan

This records the original completed increment. The subsequent saved-workout-only
revision removed the ad hoc picker and daily session/library widgets; the current
design in the linked spec takes precedence over those historical steps.

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development to implement this plan task-by-task. Each implementer receives a separate review for specification and code quality.

**Goal:** Implement user-created exercises, reusable ordered workouts, planned/manual/timed sessions, durable drafts, and shared daily totals.

**Architecture:** A validated versioned local exercise document owns library, templates, and sessions with queued durable commands. React forms consume its provider; daily interpretation supplies Home and Exercise totals.

**Tech Stack:** Existing Expo SDK 57, React Native, TypeScript, AsyncStorage, Node tests, and browser regression harness.

**Spec:** `docs/superpowers/specs/2026-10-04-exercise-v1-design.md`

## Global constraints

- Work only in Application, on `feat/exercise-v1`. User explicitly authorized implementation; use this checkout so the collaborative preview shows the work.
- No new dependencies, backend/auth integration, external writes, or modifications to KineVault.
- Reuse existing theme, Comfortaa, Font Awesome, 12px spacing, 44px actions, and shared durable-write lifecycle.
- Raw numeric drafts may be incomplete; completed logs must be strictly validated. Blank weight means zero external load, never inferred body mass.
- Preserve snapshots and dates; count only completed sessions; one globally active session.
- Separate side measurements: one set per pair, summed reps and volume. Timer uses saved wall-clock timestamp and continues across reopening.
- Every implementer gets independent specification/code review, fixes important findings, and reports exact verification evidence.

**Interfaces:** Consume Task 1's `useExercises`, document types, commands, `summarizeSessions`, `elapsedSeconds`. Parent owns mounting provider and shared daily integration. Existing Food SearchActions props must continue working without changes to Food route call sites. Exercise SearchActions requires creation callbacks and saved-workout callback; search/action row uses the existing 75/25 Food ratio. Session/list/library selectors capture selected date when opened.

- [x] Use current app components/theme patterns; keep domain logic outside route files. Prefer inline keyboard-aware panels matching Food to adding an unrelated modal/native UI dependency.
- [x] Implement ExerciseForm with name, optional metadata, Single weight/Left and right modes, save/edit/delete confirmation; cancellation preserves saved definitions.
- [x] Implement WorkoutForm with name, ordered exercise choices, up/down/remove, edit/delete confirmation, and saved-workout list with Add to day. Adding creates only a planned session.
- [x] Implement exercise search results with an explicit no-match/empty-library state. Selecting always opens a session picker listing sessions on the captured day plus New session, never silently adds to the active session.
- [x] Implement session cards with Start/Open/Log completed/Edit/confirmed Delete. Completed-only statistics reuse the domain summary. One active session timer appears above actions regardless of selected date.
- [x] Implement session editor with session name, per-exercise Add set/Remove set/Remove exercise/reorder, single reps/optional kg and independent left/right reps/optional kg. - [x] Provide Start workout, Finish workout, Log completed workout, optional manual minutes, Close, and confirmed Discard. Starting never completes sets. Finish supplies the current local draft directly to the queued completion command so a failed earlier autosave cannot lose edits.
